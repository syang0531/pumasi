# Pumasi 1.0.0

The first stable release. Pumasi turns the machines an organization
already has (Linux, macOS including old Intel Macs, Windows) into one
compute cluster: you submit jobs from anywhere, and they run on whichever
machine is free, in WASM, Docker, microVMs or on GPUs.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows: `irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The scripts check the binaries against `SHA256SUMS`. Getting started,
the command reference and the operations guide are in the
[README](../../README.md) and [docs/operations.md](../operations.md).

## What 1.0 includes

Everything an organization needs to run Pumasi on its own machines
(roadmap phases 1 to 17):

- **Running jobs**: WASM, Docker, microVMs (Firecracker, QEMU, macOS
  Virtualization.framework) and an experimental WebGPU executor; file
  inputs and outputs, a cluster file store with versioned datasets,
  priorities and preemption, cron schedules, job dependencies.
- **Machines**: release binaries for six platforms, OS services,
  signed cluster-wide upgrades with rollback, availability policies
  (on AC power, idle, hours), GPU detection and scheduling, benchmarks
  and compute units (CU).
- **Running the cluster**: role tickets (admin, submitter, viewer),
  quotas and per-account job policies, labels, taints, cordon and drain,
  metrics and alerts, a web dashboard and JSON API (`pumasi ui`),
  control-plane high availability over Raft, backups and restore.
- **Using it from anywhere**: `pumasi ui --api-only` with HTTPS and sign-in
  limits, a Cloudflare Tunnel guide, long polling.
- **Confidential work**: `trusted` and `confidential` tiers (SEV-SNP and
  TDX microVMs with remote attestation and sealed inputs and results).
- **Self-hosting (new in phase 17)**: SSO with OIDC and LDAP (groups
  mapped to roles), a tamper-evident audit log with JSON and syslog
  export, a threat model, job retention, admin secret rotation and
  per-ticket request limits.

## Security

- The internal security review of the
  [review scope](../security-review.md) is done. It fixed one high, three
  medium and six low findings; they and the one remaining risk are listed
  in the [threat model](../threat-model.md#internal-review-for-10).
- There has been **no paid third-party audit** yet ([SECURITY.md](../../SECURITY.md)).
- Every pull request runs cargo-audit, cargo-deny, CodeQL, fuzzing, a
  10-minute soak and an SSO test against real Keycloak and OpenLDAP.
  This commit also passed the long checks: 5h20m soaks on Linux and
  macOS (restarting agents and the control plane) and 20 minutes per
  fuzz target.
- Release binaries come with `SHA256SUMS` and build provenance
  attestations (`gh attestation verify pumasi-linux-x86_64 -R syang0531/pumasi`).

## Changes that need attention

- Sign-in from a terminal with SSO (`pumasi login --sso`, the device
  flow) is off unless an admin turns it on: `pumasi sso device on`. It is
  off on clusters that set up SSO before 1.0, too.
- LDAP group rules now match the full group DN. A short name like
  `group:ops` matches only groups under the configured group base.
- Jobs uploaded through the dashboard or the API can only read files
  inside their own folder.

## Known gaps

Listed in the README and [docs/architecture.md](../architecture.md):
among them, no SAML or SCIM, the audit log is never pruned, rollouts go
to every node at once, and the hub (Madang) and buying CU (phases 18 and
19) are not part of 1.0.

# Pumasi 1.0.0 (한국어 요약)

첫 정식 릴리스입니다. 조직이 이미 가진 Linux, macOS(오래된 Intel Mac 포함), Windows 장비를 하나의 컴퓨팅 클러스터로 묶어, 어디서든 작업을 제출하면 비어 있는 장비에서 WASM, Docker, microVM, GPU로 실행합니다.

- 설치: `curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh` (Windows는 `install.ps1`)
- 포함 내용: 로드맵 1~17단계 전부. 17단계에서 SSO(OIDC·LDAP), 변조를 탐지하는 감사 로그, 위협 모델, 작업 보관 기간, 관리자 시크릿 교체, 티켓별 요청 제한이 추가됐습니다.
- 보안: 내부 보안 점검을 마쳤고(높음 1, 중간 3, 낮음 6건 수정), 남은 위험 1건은 [위협 모델](../threat-model.md#internal-review-for-10)에 적었습니다. 유료 외부 감사는 아직 받지 않았습니다. 이 커밋은 Linux·macOS 5시간 20분 소크와 퍼징 타깃마다 20분 점검을 통과했습니다.
- 주의할 변경: `pumasi login --sso`(디바이스 흐름)는 관리자가 `pumasi sso device on`으로 켜야 쓸 수 있습니다. LDAP 그룹 규칙은 전체 DN으로 맞춥니다. 대시보드나 API로 올린 작업은 자기 폴더 안의 파일만 읽을 수 있습니다.
- 18·19단계(허브 마당, CU 구매)는 1.0에 들어가지 않습니다.
