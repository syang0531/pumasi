# Pumasi 1.1.0

Your own relay servers, clearer errors when a saved ticket points at the
wrong cluster, and fixes from the user report on 1.0.1.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows: `irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
Running agents pick it up with a cluster-wide upgrade
(`pumasi upgrade rollout`) or a restart with the new binary. Agents and
control planes of 1.0.x and 1.1.0 work together; nothing in the protocol
or the stored state changed.

## New

- **Your own relay.** Machines on other networks reach each other directly
  when they can and through a relay when they cannot. The relays were
  always n0's public ones; `pumasi cluster start --relay URL` now uses an
  [iroh-relay](https://github.com/n0-computer/iroh/tree/main/iroh-relay)
  server (1.x) of yours instead. Tickets carry it, so agents, `pumasi
  login`, `pumasi ui` and replicas use it without the option. See
  "Machines on other networks, and your own relay" in the README.

## Fixes

- **A saved ticket for another cluster.** When the address in the admin
  ticket now answers with another key (the cluster was created again on
  the same port, or a `pumasi login` from another cluster is left over),
  commands failed with `invalid peer certificate: UnknownIssuer`. They
  now say the ticket belongs to another or a recreated cluster, name the
  ticket file used, and point at this machine's own cluster ticket when
  that is a different cluster. `pumasi ui` checks the control plane at
  start and prints why it cannot reach it, and the `Endpoint dropped
  without calling Endpoint::close` error lines are gone.
- **`pumasi gpu check --docker-run`** reports Vulkan on its own line. On
  Windows (WSL 2) EGL/OpenGL draws on the GPU through D3D12 but Vulkan
  runs on the CPU (llvmpipe); the check said `EGL/OpenGL/Vulkan: yes`.
  It now says `Vulkan: CPU only (...)` with a note that Vulkan jobs will
  not use the GPU there.
- **Blender example** (`examples/blender-render`), rebuild the image to
  get these:
  - With Blender 5.x, EEVEE's `render device:` line said `EEVEE (GPU
    functions for drawing requires the gpu module to be initialized...)`.
    It is now printed after the first frame, when Blender knows, and
    falls back to the renderer `eglinfo` found.
  - Cycles tasks on Windows no longer print the `drawing on the CPU
    (llvmpipe)` note, which is about EEVEE only.

# Pumasi 1.1.0 (한국어 요약)

자체 릴레이 서버, 저장된 티켓이 다른 클러스터를 가리킬 때의 분명한 오류, 1.0.1 사용자 리포트 반영입니다. 1.0.x와 프로토콜·저장 형식이 같아 섞어 써도 됩니다.

- **자체 릴레이:** 다른 네트워크의 기기는 가능하면 직접, 안 되면 릴레이로 연결됩니다. 지금까지 릴레이는 n0의 공개 릴레이뿐이었는데, 이제 `pumasi cluster start --relay URL`로 자체 [iroh-relay](https://github.com/n0-computer/iroh/tree/main/iroh-relay)(1.x) 서버를 씁니다. 티켓에 들어가므로 에이전트, `pumasi login`, `pumasi ui`, 복제본은 옵션 없이 따라 씁니다.
- **다른 클러스터의 저장된 티켓:** 관리자 티켓의 주소에서 다른 키가 응답하면(같은 포트에 클러스터를 새로 만들었거나 다른 클러스터의 `pumasi login`이 남은 경우) `invalid peer certificate: UnknownIssuer`로 실패했습니다. 이제 티켓이 다른(또는 다시 만든) 클러스터의 것이라고 알려 주고, 쓴 티켓 파일과, 이 기기의 클러스터 티켓이 다르면 그 경로를 알려 줍니다. `pumasi ui`는 시작할 때 연결을 확인해 이유를 출력하고, `Endpoint dropped ...` ERROR 줄은 더 나오지 않습니다.
- **`pumasi gpu check --docker-run`:** Vulkan을 따로 표시합니다. Windows(WSL 2)에서는 EGL/OpenGL은 D3D12로 GPU에서 그리지만 Vulkan은 CPU(llvmpipe)인데 `EGL/OpenGL/Vulkan: yes`로 묶어 말했습니다. 이제 `Vulkan: CPU only (...)`와 안내를 보여 줍니다.
- **Blender 예제**(이미지를 다시 빌드하세요): Blender 5.x에서 EEVEE의 `render device:`가 무엇으로 그렸는지 말하지 않던 것을 첫 장 뒤에 확인해 출력하고, 안 되면 `eglinfo` 결과를 씁니다. Windows의 Cycles 작업에는 EEVEE용인 llvmpipe 안내를 더 찍지 않습니다.
