# Pumasi 1.12.0

Operations: the identity provider can sign people out (SCIM), the audit
log can shrink without losing its proof, every dashboard shares one set
of limits, the CLI works behind a company proxy, and followers take the
dashboard's reads off the leader.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The agent protocol (14, minor 6) and the stored state's layout (7) are
unchanged; a 1.11 cluster upgrades with `pumasi upgrade latest` (or the
dashboard's Upgrade button). Upgrade every control plane replica, then
the dashboards. Machines whose environment sets `HTTPS_PROXY` now send
relay traffic through it: see "Changed".

## New

- **SCIM provisioning.** `pumasi ui` answers SCIM 2.0 at `/scim/v2`
  (also with `--api-only`), for Microsoft Entra ID, Okta and any
  provider that speaks it. `pumasi sso scim token LABEL` prints a token
  once; `pumasi sso scim status` lists the tokens, people and groups;
  `pumasi sso scim revoke ID` stops a token.
  - Someone the provider deactivates or deletes loses every SSO ticket
    and dashboard session at once, and cannot sign in until active
    again. Someone removed from a group a `group:` rule names has their
    sessions ended, so their next sign-in gets the role the rules give
    them then.
  - SCIM never grants access; people still sign in through OIDC or LDAP.
    Every change is audited as `scim.*`.
  - Setup for Entra ID and Okta: docs/operations.md, "SCIM provisioning".
- **Audit log pruning.** `pumasi audit prune --before 365d --save
  FILE --yes` checks the whole chain, then replaces the old entries with
  a checkpoint signed by the cluster key; `pumasi audit verify` checks
  the rest from it, and `verify --against HEAD --pruned FILE` still
  checks a head saved before the prune. Without `--yes` it only says
  what would go. `pumasi cluster start --keep-audit 400d` prunes hourly
  (without saving; use it with `audit export --follow`).
- **Limits shared by every dashboard.** Dashboards run with the admin
  ticket keep their per-ticket request budgets and failed sign-in counts
  in the control plane: ten failures across two dashboards block the
  address on both. Others keep their own limits, as before.
- **Sign-in limits at the control plane.** Calls without a ticket are
  limited per machine (10, then 10 a minute) and overall, so a stranger
  who knows the cluster's address can no longer keep it asking the
  identity provider or the directory.
- **The CLI behind an HTTPS proxy.** `HTTPS_PROXY` (or `PUMASI_PROXY`,
  which wins; `off` goes direct) carries relay connections through an
  HTTP CONNECT proxy, with basic auth if the URL has it, and
  `PUMASI_CA_FILE` adds the proxy's CA for a proxy that re-signs TLS.
  For company networks; a Claude Code cloud session still uses the HTTP
  API (docs/api.md).
- **Followers answer reads.** With replicas, the leader sends the
  status, recent events and current metrics to its followers every 2
  seconds, and the dashboard's pages read them from a follower for
  admins and viewers, falling back to the leader.

## Changed

- Agents, control planes and the CLI on `--net public` use the proxy in
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` for relays. Set
  `PUMASI_PROXY=off` for a service that should ignore it.
- `pumasi audit export` warns when entries it has not sent yet were
  pruned.

## Known limits

- Keycloak has no SCIM client of its own; CI tests the requests Entra ID
  and Okta send, and the Keycloak end-to-end test plays the directory
  with curl. Filters support `eq` joined by `and`.
- Shared limits live in the leader's memory and start afresh after a
  failover.
- The API and the CLI still read from the leader; only the dashboard's
  pages use followers, and only for admins and viewers.

## Checked

- CI: two `pumasi ui` processes sharing a ticket budget, a failed
  sign-in block and SCIM requests (create through one, read and delete
  through the other); a pruned audit log that verifies, survives a
  restart and checks an older saved head; SCIM against a user signed in
  through Keycloak (`scripts/sso-e2e.sh`: deactivation ends the
  dashboard and terminal sessions and refuses the next sign-in); the CLI
  reaching a cluster only through a local CONNECT proxy and a relay with
  a private CA, and failing without the CA; a three-replica cluster
  whose follower answers a viewer and sends a submitter to the leader;
  per-peer sign-in limits.
