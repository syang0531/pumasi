# Pumasi 1.15.0

What monitoring and the dashboard had left in the CLI: per-node alert
thresholds and silences live in `cluster.toml`, the dashboard edits
schedules and secrets, its charts are pushed by the control plane, live
microVM output goes past the first MiB, Linux reads Intel and AMD GPU
temperatures and the CPU package power, agents measure the network to the
file store, and the Korean dashboard shows events and alerts in Korean.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The agent protocol is 14, minor 8 (1.14 was minor 7). The stored state
gains one table (`event_texts`) and keeps its layout (7), so
`pumasi upgrade latest` upgrades the agents and then the control plane as
in 1.14. Agents older than 1.15 keep working; they send no CPU package
power and their microVM output stops being live after 1 MiB, as before.

## New

- **Per-node thresholds and silences in `cluster.toml`.** `[alerts]` takes
  `repeat` and `resolved`, `[alerts.nodes.NAME]` and
  `[alerts.labels."SELECTOR"]` set the offline, disk and temperature
  thresholds for some nodes, and `[silences.NAME]` keeps alerts quiet
  until a date (`until = 2026-12-01T09:00:00`, in this machine's time zone
  without an offset; at most 90 days). `apply --dry-run` shows each change
  (`alerts on name=laptop: node_offline off`,
  `silence old-mac-disk: created, until ...`). A silence's id comes from
  its name, so applying the file again finds it; one the file no longer
  lists is removed only with `--prune`. With none of the tuning keys,
  `apply` leaves the thresholds alone, as before.
- **Schedules in the editor.** A schedule without `job` keeps the job it
  has, so the dashboard's `cluster.toml` editor lists the schedules (cron,
  time zone, overlap) and changes them; new schedules still need a job and
  are added on the Schedules page. The editor also shows the per-node
  thresholds.
- **Secrets in the dashboard.** Settings lists the cluster's secrets with
  when each was set, adds one, rotates one to a new value and removes one.
  A value goes to the control plane once and is never shown again; Add
  refuses a name that exists, Rotate one that does not.
- **Pushed charts.** A node's charts follow a long poll that the control
  plane answers when that node's next sample arrives, instead of asking
  every 2 seconds; against an older control plane the dashboard asks
  every 2 seconds as before. The node page also shows the CPU package
  power, and `pumasi metrics NODE` prints it.
- **Live microVM output past the first MiB.** The guest streams up to the
  4 MiB of each stream that the result keeps, from a thread that reads the
  output behind the task, so a slow console never holds the task up; what
  it has not printed when the task ends comes with the result.
- **GPU and CPU power sensors on Linux and Windows.** AMD GPUs report
  their edge temperature and power from hwmon, Intel's discrete GPUs (i915
  on Arc, xe) their temperature and power from their energy counter, and
  Intel's integrated GPUs the CPU package's temperature and RAPL's
  `uncore` power. The CPU package power comes from RAPL on Linux and from
  the SMC or IOReport on Macs (read in 1.14, sent now), in the dashboard,
  `pumasi metrics` and Prometheus (`pumasi_node_cpu_power_watts`). Windows
  reports a GPU's temperature when its driver gives one.
- **The network to the file store.** Each agent also measures the round
  trip and bandwidth to the control plane's store; `pumasi net` and the
  dashboard's matrix show it as the last column (`store`).
- **Korean events and alerts.** Each event and firing alert carries a
  message key and its arguments, and the Korean dashboard shows them in
  Korean (Overview, Events, the firing list and the silences). Events from
  before 1.15, and keys an older dashboard does not know, stay in English.

## Changed

- `apply --prune` also removes the silences a file made and no longer
  lists.
- The dashboard's editor refuses only schedules that name a job file (it
  cannot read files on its machine); job-less schedules are applied.

## Known limits

- The editor does not show the file's silences: the control plane keeps a
  silence's id, not the name it came from. The Events page lists them.
- Per-node thresholds name nodes through the `name` label, which cannot
  hold spaces.
- Windows reports a GPU's temperature but not its power; Linux reports the
  CPU package power only to an agent that can read RAPL (root, on most
  distributions).
- The 5 MiB live microVM stream is checked in CI under Linux with KVM; a
  much slower console (QEMU without acceleration) streams less of the
  output live, and the rest comes with the result.
- The Intel and AMD GPU readings are tested against a fake sysfs and the
  Windows reading compiles in CI; both are checked on real hardware by
  hand.
