# Pumasi 1.17.0

Windows: `pumasi docker remove` takes the WSL Docker away in one go, with
no restart, `pumasi docker setup` repairs a machine where someone changed
its account or task by hand, and Windows desktops without
LibreHardwareMonitor can report CPU temperatures from HWiNFO or Open
Hardware Monitor. The dashboard's `cluster.toml` editor now shows the
file's silences.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The agent protocol stays 14, minor 9, and the stored state keeps its
layout (7), so `pumasi upgrade latest` upgrades the agents and then the
control plane as in 1.16. Nothing changes for agents older than 1.17.

## New

- **`pumasi docker remove` in one go.** A WSL VM belongs to its user, and
  while the hidden `pumasi-wsl` account's VM ran, Windows kept its profile
  loaded, so 1.11 to 1.16 needed a restart and a second `remove`. Now
  `remove` first runs a one-shot task as that account
  (`\Pumasi\WSL Docker stop`) that unregisters the `pumasi-docker` distro
  and shuts the VM down, then deletes the tasks, the profile, the account
  and `C:\ProgramData\Pumasi\wsl-docker`. It exits 0 when all of it is
  gone, and also removes profiles left by an account someone deleted and
  made again by hand.
- **`pumasi docker setup` repairs.** Run again, it says what someone
  changed and puts it back: a disabled or locked-out account, a password
  that can expire, the account made an administrator, a disabled task or
  one that runs another program, has a time limit, lost its boot trigger
  or no longer logs on by itself. The task also provisions the distro
  again when its `wsl.conf` or start script was edited.
- **Windows CPU temperatures without LibreHardwareMonitor.** Windows has
  no API for them and Pumasi ships no kernel driver, so the agent reads
  the hardware monitor the owner runs: LibreHardwareMonitor as before, and
  now [HWiNFO](https://www.hwinfo.com/) (with "Shared Memory Support" on)
  and Open Hardware Monitor. Agents that do not run as administrator read
  the ACPI thermal zones through the "Thermal Zone Information" counters.
  `pumasi sensors --raw` on Windows lists every source and reading. See
  README "Windows temperatures".
- **Silences in the dashboard's editor.** The `cluster.toml` editor writes
  the `[silences.NAME]` a `cluster.toml` made, with their rule, nodes,
  until and comment, so editing and applying the file keeps them.

## Changed

- "Distance to TjMax" sensors (LibreHardwareMonitor, HWiNFO) no longer
  count as temperatures; they could make a cool CPU look hot.
- A `cluster.toml` silence is stored by `cluster.toml/NAME` instead of
  `cluster.toml`. Silences from 1.15 and 1.16 keep working; applying the
  file once more rewrites them with their names (the preview says
  "updated" once), and from then on the editor shows them.

## Not in this release

- **HCS backend.** It waits for `scripts/windows/boot-times.ps1` numbers
  from real PCs; without them there is nothing to decide. QEMU with WHPX
  stays the Windows microVM backend.
- **Signed Windows binaries.** SignPath Foundation has not approved the
  project yet; the release workflow's `sign` job is ready and skipped until
  then, so Smart App Control may still block installs (README "Smart App
  Control").

## Known limits

- The hardware monitors start with a sign-in, so a Windows machine nobody
  has signed into since it booted reports only its ACPI thermal zones. The
  free HWiNFO turns shared memory off after 12 hours.
- The monitors' readings are checked against recorded data and a stand-in
  for HWiNFO's mapping in CI (runners have no sensors), and on real PCs by
  hand.
- Silences made on the Events page or with `pumasi alert silence` have no
  name and stay off the editor.

## 한국어 요약

- **`pumasi docker remove`가 한 번에 끝납니다.** 숨김 계정 `pumasi-wsl`로 도는 1회용 작업이 배포판 등록을 해제하고 WSL VM을 끈 뒤 작업·프로필·계정·폴더를 지웁니다. 재부팅이 필요 없고, 모두 지워지면 0으로 끝납니다.
- **`pumasi docker setup`이 고칩니다.** 계정(사용 안 함, 잠김, 암호 만료, 관리자로 바뀜)과 예약 작업(사용 안 함, 다른 프로그램, 시간 제한, 부팅 트리거·저장 암호 로그온이 빠짐)을 손으로 바꿨으면 무엇을 고쳤는지 말하고 되돌립니다. 배포판의 `wsl.conf`나 시작 스크립트가 바뀌어도 다시 설정합니다.
- **LibreHardwareMonitor 없이도 Windows CPU 온도.** Pumasi는 커널 드라이버를 넣지 않으므로, 소유자가 실행하는 HWiNFO("Shared Memory Support" 켬)나 Open Hardware Monitor를 읽습니다. 관리자 권한 없는 에이전트도 열 영역 카운터를 읽습니다. `pumasi sensors --raw`가 출처별 값을 보여 줍니다.
- **편집기에 일시 중지.** 대시보드의 `cluster.toml` 편집기가 파일로 만든 `[silences.이름]`을 보여 줍니다. 1.15·1.16에서 만든 것은 파일을 한 번 더 적용하면 이름과 함께 다시 저장됩니다(미리 보기에 한 번 "updated").
- "Distance to TjMax" 센서는 더 이상 온도로 치지 않습니다.
- HCS 백엔드는 실제 PC의 `boot-times.ps1` 결과를, 서명은 SignPath 승인을 계속 기다립니다.
- 에이전트 프로토콜(14, minor 9)과 저장 레이아웃(7)은 그대로입니다.
