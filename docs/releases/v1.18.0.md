# Pumasi 1.18.0

MicroVM networks grow up: UDP (so QUIC), IPv6 where the host has it,
per-job allow lists such as `network = ["pypi.org:443"]` and bandwidth
caps, and the bytes a task sent and received on the receipt, billed at
the price list's egress rate. Firecracker gets a network without QEMU
when the agent runs as root on Linux. Private images are pulled from the
registry once and taken from the file store after that, and node caches
get a size and a per-account share from node labels, evicting what queued
jobs need last.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The agent protocol stays 14 and goes to minor 10; the stored state keeps
its layout (7) and gains one table. `pumasi upgrade latest` upgrades the
agents and then the control plane as before. Jobs with an allow list or a
cap go only to 1.18 agents, and a control plane older than 1.18 refuses
them (instead of running them with the whole internet), so upgrade the
control plane (every replica) before submitting them. Everything else
works with older agents as in 1.17.

## New

- **Allow lists and bandwidth caps for microVM jobs.** In a job file:

  ```toml
  executor = "microvm"
  image = "python:3.12-slim"
  network = ["pypi.org:443", "*.pythonhosted.org:443", "203.0.113.0/24"]
  # or, with a cap in megabits per second each way:
  # network = { allow = ["pypi.org:443"], mbps = 20 }
  ```

  A rule is a host name (`*.name` for its subdomains), an address or a
  range, with an optional port or port range (`:443`, `:8000-8100`).
  The gateway answers DNS only for names on the list (NXDOMAIN for the
  rest) and opens connections, TCP or UDP, only to addresses the list
  names or that DNS gave for a listed name. The private-range blocking
  stays underneath: an address on the list that is private, the host's
  own, or port 25 is still refused. `network = { mbps = 20 }` caps a job
  that may reach every public address. Docker jobs cannot take a list
  (their network is all or nothing), so an `executor = "image"` job with
  one runs as a microVM. The API's `?validate=1` checks the list too.
- **UDP and IPv6.** The gateway forwards UDP to allowed public addresses
  (one host socket per flow, 256 flows at most, idle ones closed after two
  minutes), so QUIC and DNS to outside resolvers work; refused UDP gets a
  port-unreachable. Where the host has IPv6 the guest also gets
  `fd00:5055:4d41::15/64` behind the gateway's `fd00:5055:4d41::2`, and
  AAAA answers; public IPv6 is 2000::/3 without the documentation, 6to4
  and Teredo ranges.
- **Egress on the receipt.** The agent counts what each task's guest sent
  and received (payload bytes, TCP and UDP; DNS to the gateway is free),
  signs the figure with its node key, and the control plane bills both
  directions at the price list's `egress_gib` rate (0.1 CU per GiB by
  default; nothing when the provider is the consumer). The figure it
  bills is capped by the job's cap, or 10 Gbit/s, times the billed time.
  `pumasi receipts` lists it under the table (sent, received, billed,
  CU), and receipts with egress use version 4 of the receipt format
  (`pumasi/receipt/cluster/v4`); 1.17 clients keep getting the receipt
  without the egress part.
- **Firecracker with a network, without QEMU.** An agent running as root
  on Linux makes a TAP device per network task (`pmtap0`, ...) and joins
  it to the same user-space gateway, so the allow list, the caps and the
  blocking are the same as under QEMU; the host does no routing or NAT.
  Devices left by a crashed agent are removed at the next start. As a
  user, or with QEMU installed, nothing changes.
- **Private images through the store.** The control plane keeps each
  private image it pulled under `imgc/<arch>/<digest>` (32 at most, a week
  after their last use) and takes the next job's image from there: a
  reference by digest asks the registry nothing, a tag only for its
  manifest after ten minutes. Nodes fetch the layers from the closest copy
  as before, so a 4-task job on two nodes pulls from the registry once.
- **Node cache quotas.** Node labels set a node's file store cache:
  `cache=50G` replaces the agent's own `--store-cache`, and
  `cache.account=10G` caps what one account's collections may take. The
  control plane sends each node the collections queued jobs will mount;
  eviction drops an account's entries over its share first, then the
  least recently used, and what the queue needs last. Set the labels like
  any other: `pumasi label NODE cache=50G`, `cluster.toml` or the
  dashboard.

## Changed

- A job file's `network` takes `true`/`false`, a list, or a table;
  `network = []` is refused (it would reach nothing).
- Schedules refuse jobs with an allow list or a cap for now: the schedule
  record has no room for them, and its runs would reach everything.

## Not in this release

- **HCS backend and signed Windows binaries** still wait for real-PC
  `boot-times.ps1` numbers and SignPath's approval (unchanged since 1.17).

## Known limits

- Allow lists and caps are microVM-only. A listed name opens the
  addresses DNS gave the guest for it, so a guest reaches such an address
  only after asking for the name.
- A cap paces each direction with a token bucket; the burst is a quarter
  second of the rate (32 KiB at least).
- The guest prefers IPv4 where a name has both; IPv6 needs IPv6 on the
  host, and ICMP is not forwarded.
- Egress is the node's signed figure; the control plane bounds it by the
  cap and the billed time but cannot see the traffic itself.
- "A microVM job on the iMac reaches only its allow list" is checked by
  hand (vz backend; GitHub's Mac runners cannot run VMs).

## 한국어 요약

- **microVM 작업의 허용 목록과 대역폭 상한.** 잡 파일에 `network = ["pypi.org:443", "*.pythonhosted.org:443"]` 또는 `network = { allow = [...], mbps = 20 }`. 게이트웨이는 목록에 있는 이름만 DNS로 답하고(나머지는 NXDOMAIN), 목록의 주소나 목록 이름의 DNS 답 주소로만 TCP·UDP 연결을 엽니다. 사설 대역·호스트 주소·25번 포트 차단은 그대로라 목록에 있어도 막힙니다. Docker 작업은 목록을 받지 않고, `executor = "image"`는 microVM으로 돕니다.
- **UDP와 IPv6.** 허용된 공인 주소로 UDP를 넘기므로 QUIC과 외부 DNS가 됩니다. 호스트에 IPv6가 있으면 게스트도 `fd00:5055:4d41::15/64`를 받습니다.
- **영수증의 이그레스.** 에이전트가 태스크별 송수신 바이트를 세어 노드 키로 서명하고, 컨트롤 플레인이 양방향을 요금표의 `egress_gib`(기본 GiB당 0.1 CU)로 과금합니다. 상한(없으면 10 Gbit/s)×과금 시간으로 묶습니다. `pumasi receipts` 표 아래에 송수신·청구 바이트·CU, 영수증 형식 v4. 1.17 클라이언트는 이그레스 없이 받습니다.
- **QEMU 없는 Firecracker 네트워크.** Linux에서 root로 도는 에이전트는 태스크마다 TAP 장치를 만들어 같은 사용자 공간 게이트웨이에 붙입니다.
- **비공개 이미지는 한 번만 받습니다.** `imgc/<arch>/<digest>`로 저장소에 두고 다음 작업은 거기서 가져옵니다(digest 참조는 레지스트리에 묻지 않고, 태그는 10분 뒤 manifest만).
- **노드 캐시 쿼터.** 노드 라벨 `cache=50G`(에이전트의 `--store-cache` 대신), `cache.account=10G`(계정별 몫). 큐에 있는 작업이 마운트할 것은 마지막에 지웁니다.
- 스케줄은 허용 목록·상한이 있는 작업을 아직 받지 않습니다.
- 에이전트 프로토콜 14, minor 10. 저장 레이아웃 7(테이블 하나 추가). 허용 목록 작업은 컨트롤 플레인(모든 복제본)을 먼저 올린 뒤 제출하세요.
- HCS와 서명은 계속 실제 PC 측정값과 SignPath 승인을 기다립니다.
