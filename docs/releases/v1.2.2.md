# Pumasi 1.2.2

Upgrade fixes found while moving a three-machine cluster to 1.2.1.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
Nothing changed in the protocol or the stored state.

## Fixes

- **A rollout never downgrades.** A rollout stays on until it is
  cancelled, so a node upgraded by hand past it (say, to 1.2.1 while a 1.2.0
  rollout was still on) got the older binary back the next time it was
  idle. The control plane now counts a node that runs a newer version than
  the rollout's as current, and the agent refuses a release older than
  itself ("refusing to downgrade").
- **Windows: upgrading a binary that several services run.** When the
  agent, the control plane and the dashboard ran from one `pumasi.exe`, a
  rollout could fail with "move ... aside: access denied": the previous
  binary, still running in another service, held the `pumasi.exe.old`
  name. The running binary now moves to `pumasi.exe.old-<n>` in that case,
  and leftovers are deleted at the next start. `install.ps1` does the same.
- **`install.ps1` from a non-administrator PowerShell.** `pumasi` was not
  found right after installing when the install folder was already on the
  user PATH from an earlier install but not on that window's. The folder is
  now added to the window's PATH too, and the script says that a
  non-administrator install goes to the user folder and that services need
  an administrator PowerShell.

## 한국어 요약

- **배포가 버전을 내리지 않습니다.** 배포는 취소할 때까지 살아 있어서, 배포 중에 손으로 더 새 버전을 깐 노드(예: 1.2.0 배포 중 1.2.1 설치)가 다시 예전 바이너리를 받았습니다. 이제 컨트롤 플레인은 더 새 버전을 도는 노드를 최신으로 보고, 에이전트도 자기보다 오래된 릴리스를 거부합니다.
- **Windows에서 여러 서비스가 같은 exe를 쓸 때 업그레이드 실패**("move ... aside: 액세스 거부")를 고쳤습니다. 이전 바이너리가 다른 서비스에서 아직 돌며 `pumasi.exe.old` 이름을 잡고 있던 경우로, 이제 `pumasi.exe.old-<n>`으로 옮기고 다음 시작 때 지웁니다. `install.ps1`도 같습니다.
- **관리자가 아닌 PowerShell에서 `install.ps1`**: 설치 직후 `pumasi`를 못 찾던 문제를 고쳤고, 서비스 설치에는 관리자 PowerShell이 필요하다고 알려 줍니다.
