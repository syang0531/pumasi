# Pumasi 1.2.3

The web dashboard behind Cloudflare Tunnel, and a Windows install fix.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
Nothing changed in the protocol or the stored state.

## Fixes

- **The dashboard behind a tunnel answered `421 unexpected Host
  header`.** On loopback, `pumasi ui` accepts only `127.0.0.1`,
  `localhost` and `[::1]` as the Host (against DNS rebinding), so pages
  served through Cloudflare Tunnel or a reverse proxy on the same machine,
  which carry the public name, were refused; only `--api-only` worked
  there. The name in `--public-url` is now accepted too, and signing in
  from that name passes the same-origin check:

  ```sh
  pumasi ui --listen 127.0.0.1:7400 --login-only \
    --public-url https://pumasi.example.com --real-ip-header CF-Connecting-IP
  ```

  serves the pages and `/api/v1` (bearer tickets) on one name. docs/api.md
  ("Put it on the internet") covers it, and setting the tunnel up from the
  Cloudflare dashboard.
- **`install.ps1`: other accounts could not run `pumasi.exe`.** The binary
  kept the permissions of the temporary folder it was downloaded to, so
  only SYSTEM, Administrators and the installing user could run it from
  Program Files. It now takes the install folder's permissions (README has
  the fix for existing installs).

## 한국어 요약

- **터널 뒤 대시보드가 `421 unexpected Host header`로 막히던 문제**를 고쳤습니다. 루프백에서 `pumasi ui`는 DNS 리바인딩을 막으려고 `127.0.0.1`·`localhost`·`[::1]`만 Host로 받아서, 같은 기기의 Cloudflare Tunnel이나 리버스 프록시를 거친 공개 이름의 요청을 거부했습니다(`--api-only`만 됐음). 이제 `--public-url`의 이름도 받고, 그 주소에서의 로그인도 같은 출처로 봅니다. `pumasi ui --listen 127.0.0.1:7400 --login-only --public-url https://pumasi.example.com --real-ip-header CF-Connecting-IP`로 화면과 `/api/v1`을 한 주소에서 제공합니다.
- **`install.ps1`로 설치한 `pumasi.exe`를 다른 계정이 실행하지 못하던 문제**를 고쳤습니다. 이제 설치 폴더의 권한을 따릅니다.
