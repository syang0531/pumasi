# Pumasi 1.22.0

Monitoring. Every run says how much electricity it took (watt-hours from
the CPU package's and the GPUs' power, shared among the node's runs);
each node can have an electricity price, with cheaper night hours, and
`pumasi energy` shows per day what a node's power cost against the CU
its runs were worth and earned; a node that stays over a temperature
stops taking tasks; `pumasi bench --estimate` tells a machine's owner
what it would earn and cost before joining; Linux agents not run as root
can read the CPU's power; alerts reach Telegram, ntfy and email; and
hourly metrics can be kept for months.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The agent protocol stays 14, minor 12; the stored state keeps its layout
(7). `pumasi upgrade latest` upgrades the agents and then the control
plane as before. Agents older than 1.22 report no energy. The new
commands, settings and alert formats need a 1.22 control plane; a
cluster with replicas upgrades them together.

## New

- **Energy per run.** The agent integrates the CPU package's power
  (RAPL on Linux, the SMC or IOReport on Macs, a hardware monitor on
  Windows) and each GPU's over every run. The CPU's share follows the
  run's CPU time against everything busy on the machine (other programs
  keep theirs); a GPU's power is split among the runs holding it.
  `pumasi job`, `describe job`, the dashboard's "Attempts and usage"
  table and `GET /api/v1/jobs/ID/runs` show it per attempt and in total:

  ```
  $ pumasi job 7c1e04b2d9a8f310
  ...
    used: cpu 41.2s  memory 1.1 GiB ...
    energy: 3.84 Wh (CPU 1.21 Wh, GPU 2.63 Wh)
    [0] attempts:
        attempt 1 node=gpu-pc ok 61200ms  cpu 41.2s ...  3.84 Wh (CPU 1.21 Wh, GPU 2.63 Wh)
  ```

- **Electricity against earnings.** A price per node, in won per kWh,
  with optional cheaper hours (KEPCO's time-of-use plans change price on
  the hour):

  ```sh
  pumasi node set gpu-pc --electricity-price 120 --cheap-hours 23-07@80
  pumasi energy --days 7
  ```

  ```
  DAY        NODE                 ENERGY  HOURS        COST     WORTH    EARNED   WON/CU  RUNS
  2026-11-18 gpu-pc             2.35 kWh   24.0     248 won     48.00      12.5      5.2    31
  ```

  The control plane adds up each node's measured power by hour of its
  local time and, from receipts, what the node's runs were worth at the
  cluster's prices (also the owner's own runs, which move no CU) and
  what other accounts paid it. `--by-account` sums the nodes of each
  account, `-o json` gives everything. The settings live on the control
  plane (no agent restart) and in `cluster.toml`:

  ```toml
  [nodes.gpu-pc]
  electricity_price = 120
  cheap_hours = "23-07@80"
  max_temperature = 85
  ```

  The dashboard's Nodes page has an "Electricity and earnings" table and
  each node's page a form for its price, cheap hours and temperature
  limit.
- **Pausing when hot.** `pumasi node set imac --max-temperature 85`:
  when the node's hottest CPU or GPU sensor stays over 85 °C for a
  minute it takes no new tasks (a `node.paused` event; `pumasi status`
  says "imac is paused: over 85 °C for a minute") until it stays under for a minute.
  With the agent's `--on-pause requeue` its running tasks move too, as
  for its other pause rules.
- **An estimate before joining.**

  ```
  $ pumasi bench --estimate --price 120
  ...
  estimate at full load (the cluster's rates):
           CPU    15.2 CU/h (16 vCPUs at score 950 each)
           memory 7.35 CU/h (29.4 GiB, 2 GiB left to the system)
           GPU    5.977 CU/h
           total  28.527 CU/h
           power  142 W (CPU package at full load; GPUs not counted, give --watts)
           cost   17.0 won/h, 0.60 won per CU earned
  ```

  The rates come from the cluster when `pumasi login` saved a ticket,
  else the defaults; `--watts 350` takes a power meter's figure for the
  whole machine.
- **CPU power without root on Linux.** Since kernel 5.10 only root reads
  RAPL. `sudo pumasi service rapl --add-user stan` writes
  `/etc/udev/rules.d/60-pumasi-rapl.rules`, which gives the counters to
  the `pumasi` group, creates the group and adds the user; `--dry-run`
  prints the rule. `sudo pumasi service install` of a system agent
  writes the rule too, and a user install says when the CPU's power is
  unreadable.
- **Telegram, ntfy and email alerts.**

  ```sh
  pumasi webhook add tg "https://api.telegram.org/bot<TOKEN>/sendMessage?chat_id=<ID>"
  pumasi webhook add phone https://ntfy.sh/my-cluster-7f3a
  pumasi webhook add home-ntfy https://me:pw@ntfy.example.com/pumasi --format ntfy
  pumasi webhook add mail "smtp://me:app-password@smtp.gmail.com:587?from=me@gmail.com&to=me@gmail.com,ops@example.com"
  ```

  Each sends a test alert when added (`pumasi webhook test NAME` later).
  ntfy notices carry a priority (urgent for a firing critical alert) and
  tags; email is plain text over STARTTLS (`smtp://`, required unless
  the server is on the same machine) or TLS (`smtps://`, port 465). The
  dashboard's Events page offers the new formats.
- **Longer history.** `pumasi cluster start --keep-metrics 365d` keeps
  one point an hour per node for that long, beyond
  `--metrics-retention`, so `pumasi metrics NODE --since 90d` and the
  charts reach back months. Off by default.
- **API:** `GET /api/v1/energy?days=30` and
  `PUT /api/v1/nodes/NODE/energy` with `{"price": 120, "cheap": {"from":
  23, "to": 7, "price": 80}, "max_temp_c": 85}` (admin).

## Fixed and changed

- The dashboard's webhook list shows the format's name as the CLI does.
- `pumasi webhook ls` asks for the true formats; a 1.21 client shows
  Telegram, ntfy and email webhooks as `json`.

## Known limits

- Watt-hours are shown, not billed, and are not in receipts (signed
  receipts stay as they were).
- A WASM run counts as one busy core when the CPU's power is shared.
- A day is priced at the node's price as it is now.
- The temperature pause is not stored: after a control plane restart a
  hot node works until it has been over its limit for another minute.
- `bench --estimate` reads only the CPU package's power; give `--watts`
  for GPUs, the board and the power supply.
- Getting an alert on the phone and the RTX 3080 PC's day of earnings
  against its power are checked by hand.

## 한국어 요약

- **실행별 전력량.** 에이전트가 CPU 패키지 전력(Linux RAPL, Mac SMC·IOReport, Windows 하드웨어 모니터)과 GPU 전력을 실행마다 적분합니다. CPU 몫은 기기 전체 사용량 대비 그 실행의 CPU 시간으로, GPU 전력은 그 GPU를 쓰는 실행끼리 똑같이 나눕니다. `pumasi job`, `describe job`, 대시보드 "시도와 사용량" 표, `GET /api/v1/jobs/ID/runs`가 시도별·합계로 보여 줍니다.
- **전기요금 대비 수익.** `pumasi node set gpu-pc --electricity-price 120 --cheap-hours 23-07@80`(원/kWh, 저렴한 시간대는 정시 단위). `pumasi energy [--days 7] [--by-account] [-o json]`이 노드별·날짜별(컨트롤 플레인 현지 시각) 전력량, 비용, 실행의 CU 가치(내 계정 실행 포함)와 다른 계정에서 번 CU, 원/CU를 보여 줍니다. 설정은 컨트롤 플레인에 저장되어 에이전트가 재시작하지 않으며, `cluster.toml`의 `[nodes.이름]`(`electricity_price`, `cheap_hours`, `max_temperature`)에도 둘 수 있습니다. 대시보드 노드 화면에 "전기와 수익" 표와 노드별 설정 폼이 있습니다.
- **온도가 넘으면 멈추기.** `--max-temperature 85`면 가장 뜨거운 CPU·GPU 센서가 1분 넘게 85 °C를 넘을 때 새 태스크를 받지 않고(`node.paused` 이벤트), 1분 동안 내려가 있으면 다시 받습니다. 에이전트가 `--on-pause requeue`면 실행 중인 태스크도 옮깁니다.
- **참가 전 예상.** `pumasi bench --estimate --price 120`이 최대 부하에서 시간당 CU(로그인한 클러스터 단가, 없으면 기본값), 벤치마크 중 잰 CPU 패키지 전력, 시간당·CU당 전기요금을 보여 줍니다. GPU까지 포함하려면 전력계 값을 `--watts`로 주세요.
- **Linux에서 root 없이 CPU 전력.** `sudo pumasi service rapl --add-user 사용자`가 `/etc/udev/rules.d/60-pumasi-rapl.rules`를 써서 `pumasi` 그룹이 RAPL을 읽게 하고, 그룹을 만들고 사용자를 넣습니다(`--dry-run`은 규칙만 출력). 시스템 에이전트를 `service install`하면 같은 규칙을 씁니다.
- **Telegram·ntfy·이메일 경보.** `pumasi webhook add`에 Telegram `sendMessage` URL(`chat_id` 포함), `https://ntfy.sh/토픽`(자체 서버는 `--format ntfy`), `smtp://사용자:비밀번호@호스트:587?from=...&to=...`(STARTTLS 필수, 같은 기기 릴레이는 예외) 또는 `smtps://`(465)를 줍니다. 추가할 때 시험 경보를 보냅니다.
- **더 긴 기록.** `pumasi cluster start --keep-metrics 365d`면 노드 지표를 한 시간에 한 점씩 그 기간 보관합니다(기본은 끔).
- **API.** `GET /api/v1/energy?days=30`, `PUT /api/v1/nodes/NODE/energy`(관리자).
- 에이전트 프로토콜 14(minor 12), 저장 레이아웃 7 그대로. 1.22 이전 에이전트는 전력량을 보내지 않고, 새 명령·설정·경보 형식은 1.22 컨트롤 플레인이 필요합니다. 복제본이 있는 클러스터는 함께 업그레이드하세요.
- 알려진 한계: 전력량은 표시만 하고 청구하지 않으며 영수증에는 들어가지 않음, WASM 실행은 CPU 1코어로 계산, 하루 비용은 지금 요금으로 계산, 온도 정지는 컨트롤 플레인을 재시작하면 1분 뒤 다시 걸림, `bench --estimate`는 CPU 패키지 전력만 잼, 휴대폰 경보 수신과 RTX 3080 PC의 하루 수익 대비 전력은 수동 확인.
