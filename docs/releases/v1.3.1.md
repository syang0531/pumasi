# Pumasi 1.3.1

Upgrades reach a machine that runs only the control plane.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The protocol (14) and the stored state's layout (7) are unchanged. A 1.3.0
control plane with an agent on its machine upgrades to 1.3.1 with
`pumasi upgrade latest` (or the dashboard's Upgrade button); one without
an agent needs the install script once, on its machine.

## Fixed

- **A control plane without an agent on its machine is upgraded too.** In
  1.3.0 the control plane and the dashboard restarted into a new release
  only after the agent on their machine had installed it, so on a machine
  that runs only the control plane, `pumasi upgrade latest` upgraded every
  node but left the control plane behind (and said there was nothing to
  roll out once the nodes were current). Now the control plane also
  fetches the release for its own platform when it is behind, and, when
  no agent on its machine is a member of the cluster, the leading control
  plane installs that binary over its own (checked against the release's
  SHA-256 and started with `--version` first). It and the dashboard then
  restart into it once the rollout has settled, as before. Binaries
  rolled out with `pumasi upgrade rollout` are installed the same way.
  With a member agent on the machine nothing changes: the agent installs
  the binary and rolls back if it fails.
- The dashboard's Upgrade panel and the docs say so, and
  `docs/operations.md` has the steps to take the agent off a machine that
  should run only the control plane (drain, `pumasi service uninstall
  agent`, `pumasi remove-node`).

## 한국어 요약

- **에이전트가 없는 컨트롤 플레인 PC도 업그레이드됩니다.** 1.3.0에서는 같은 PC의 에이전트가 새 버전을 설치해야 컨트롤 플레인과 대시보드가 따라 올라갔기 때문에, 컨트롤 플레인만 도는 PC는 `pumasi upgrade latest`(대시보드 업그레이드 버튼)를 눌러도 남아 있었습니다. 이제 컨트롤 플레인이 자기 플랫폼용 릴리스도 받고, 같은 PC에 멤버 에이전트가 없으면 SHA-256과 `--version` 확인 뒤 자기 바이너리를 직접 교체합니다. 롤아웃이 끝나면 컨트롤 플레인과 대시보드가 새 버전으로 재시작합니다. 같은 PC에 에이전트가 있으면 지금처럼 에이전트가 설치합니다.
- **처음 한 번은** 에이전트가 없는 1.3.0 컨트롤 플레인 PC에서 설치 스크립트로 1.3.1을 올려야 합니다. 그다음부터는 업그레이드 버튼 하나로 컨트롤 플레인 PC까지 올라갑니다.
- `docs/operations.md`에 PC를 컨트롤 플레인 전용으로 바꾸는 순서(drain, `pumasi service uninstall agent`, `pumasi remove-node`)를 적었습니다.
