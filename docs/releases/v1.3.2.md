# Pumasi 1.3.2

MicroVMs boot on Intel Macs.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The protocol (14) and the stored state's layout (7) are unchanged; a 1.3.1
cluster upgrades with `pumasi upgrade latest` (or the dashboard's Upgrade
button).

## Fixed

- **Intel Macs (vz): microVMs hung until their timeout.** On an Intel Mac,
  Virtualization.framework enters a Linux kernel through its EFI stub, and
  the x86_64 guest kernel (built from Firecracker's configuration) had no
  EFI, so the VM never ran an instruction: `pumasi vm run` and microVM
  jobs stopped at "unpacking image in a build VM" with an empty console.
  Found on a 2014 iMac on Big Sur. The new kernel,
  `guest-kernel-6.1.155-2`, has the EFI stub. An agent replaces the old
  kernel by itself when it starts (so `pumasi upgrade latest` is enough),
  and so does `pumasi vm setup`. Apple Silicon Macs were not affected.
  This also makes the 1.3.0 microVM network usable on Intel Macs.

## 한국어 요약

- **Intel Mac(vz)에서 microVM이 시간 제한까지 멈춰 있던 문제**를 고쳤습니다. Intel Mac의 Virtualization.framework는 리눅스 커널의 EFI 스텁으로 부팅하는데, x86_64 게스트 커널(Firecracker 설정으로 빌드)에 EFI가 없어 VM이 명령어 하나도 실행하지 못했습니다(`pumasi vm run`과 microVM 작업이 "unpacking image in a build VM"에서 멈추고 콘솔이 비어 있음). Big Sur를 쓰는 2014년 iMac에서 찾았습니다. 새 커널 `guest-kernel-6.1.155-2`에는 EFI 스텁이 있고, 에이전트가 시작할 때 옛 커널을 스스로 바꾸므로 `pumasi upgrade latest`만 하면 됩니다(`pumasi vm setup`도 바꿈). Apple Silicon Mac은 영향이 없었습니다. 1.3.0의 microVM 네트워크도 이제 Intel Mac에서 쓸 수 있습니다.
