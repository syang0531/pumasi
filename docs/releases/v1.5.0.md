# Pumasi 1.5.0

Machines that sleep, and image jobs on machines without Docker. A
desktop or laptop that lends itself now stays awake while it works, says
so before it sleeps (its tasks move at once and nobody is alerted), and
can be woken over the LAN when work is waiting. `executor = "image"`
runs the same image in Docker where a node has Docker and in a microVM
where it does not.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The protocol (14) and the stored state's layout (7) are unchanged; a 1.4
cluster upgrades with `pumasi upgrade latest` (or the dashboard's Upgrade
button), in any order. What is new needs both sides on 1.5: a 1.5 agent
under a 1.4 control plane only keeps its machine awake, and a 1.4 agent
in a 1.5 cluster is never shown as asleep and sends no magic packets.

## New

- **The agent keeps its machine awake while tasks run**, and for 30
  seconds after the last one: a power assertion on macOS, a power
  request on Windows, `systemd-inhibit` on Linux. Only the idle timer is
  held back; the display still turns off, and the lid, the power button
  and the Sleep menu still work. `--allow-sleep` turns it off.
- **A machine says goodbye before it sleeps.** The control plane moves
  its running tasks to other nodes at once, instead of after the node
  timeout, and the move costs them no attempt. The node shows as
  `asleep` in `pumasi status`, the dashboard and the API, a `node.asleep`
  event replaces `node.offline`, and the `node_offline` alert does not
  fire. The agent reconnects when the machine wakes.
- **Wake-on-LAN.** With `--wake-on-lan` on a node's agent, the cluster
  sends its magic packet when work is waiting: at once for work that no
  online node can run, and after `--wake-after` (a control plane option,
  default `10m`, `never` to turn it off) for work that waits for busy
  nodes. The packet comes from the machines of the cluster on the node's
  LAN: the control plane when it is there, and up to two online agents.
  By hand: `pumasi node wake NODE`, the **Wake** button on the
  dashboard's node page, or `POST /api/v1/nodes/NODE/wake`. `pumasi node
  NODE` shows the node's network cards and whether the cluster can reach
  them. The README lists the
  [macOS, Windows, Linux and BIOS settings](../../README.md#machines-that-sleep).

  ```sh
  pumasi service set -- --wake-on-lan      # on the machine that may be woken
  pumasi node wake laptop
  ```
- **`executor = "image"`.** An image job whose tasks run in Docker on
  nodes with Docker and in a microVM on nodes with only microVMs (old
  Macs, PCs without Docker Desktop). `pumasi job ID` prints `as=docker`
  or `as=microvm` per task, the API has `ran_as`, and the dashboard's job
  page shows it; each task is billed at the rate of what it ran as. The
  confidential tier settles an image job on microVMs and
  `gpu.capabilities` on Docker; an account policy that allows only one
  of the two narrows it to that one. Example:
  `examples/python-wordcount/job-image.toml`.
- **`--idle-minutes` works for the Windows service.** The agent service
  starts a helper without a window (`pumasi idle-helper`) in the
  signed-in user's session and reads the idle time from it. With nobody
  signed in, the machine is idle. Nothing to set up; before 1.5 the
  service could not tell and stayed paused.
- **`--on-pause requeue`.** When a machine pauses (on battery, someone at
  the keyboard, outside its hours), its running tasks move to other
  nodes at once instead of finishing there. The default stays `finish`.
- **A guide for Linux on 2013-2014 Macs**:
  [docs/linux-on-old-macs.md](../linux-on-old-macs.md) (Docker, KVM
  microVMs and Vulkan in place of macOS's limits).
- `GET /api/v1/status` carries `power` for each node: asleep since when,
  what its agent does about sleep, its LAN cards, the last magic packet,
  and whether the cluster can wake it.

## Notes

- Turn the new agent options on with `pumasi service set`, for example
  `pumasi service set -- --wake-on-lan --on-pause requeue`.
- The agent does not change the machine's Wake-on-LAN settings, and
  Wi-Fi cards rarely wake from a magic packet. A cluster with only one
  machine on a LAN cannot wake that machine.
- Only nodes that said goodbye are woken automatically. A machine that
  was shut down or lost power is `offline`; `pumasi node wake` still
  sends its packet.
- The blocker does not stop a sleep its owner asks for (lid, power
  button, Sleep menu); that is the goodbye case.
- The Windows idle helper was planned as a scheduled task with a named
  pipe; it is started by the service instead, so there is nothing to
  install or remove.
- A CLI or dashboard older than 1.5 cannot show an image job. Upgrade
  them with the control plane.
- Checked by hand, not in CI: real sleep and wake on a Mac and a Windows
  PC, and a real magic packet waking a machine.

## 한국어 요약

- **태스크 실행 중에는 기기를 깨워 둡니다.** 마지막 태스크가 끝나고 30초 뒤까지 유휴 잠자기를 막습니다(macOS 전원 어서션, Windows 전원 요청, Linux `systemd-inhibit`). 화면은 꺼지고, 덮개·전원 버튼·잠자기 메뉴는 그대로 동작합니다. `--allow-sleep`으로 끕니다.
- **잠들기 전에 알립니다.** 컨트롤 플레인이 노드 타임아웃을 기다리지 않고 그 기기의 태스크를 바로 다른 노드로 옮기며, 시도 횟수는 줄지 않습니다. 노드는 `pumasi status`, 대시보드, API에서 `offline`이 아니라 `asleep`으로 보이고 `node_offline` 경보도 울리지 않습니다. 기기가 깨면 에이전트가 스스로 다시 연결합니다.
- **Wake-on-LAN.** 에이전트를 `--wake-on-lan`으로 실행한 노드는 대기 작업이 있을 때 클러스터가 매직 패킷으로 깨웁니다. 온라인 노드가 못 돌리는 작업이면 바로, 바쁜 노드를 기다리는 작업이면 `--wake-after`(컨트롤 플레인 옵션, 기본 `10m`, `never`로 끔) 뒤입니다. 패킷은 같은 LAN에 있는 클러스터 기기(컨트롤 플레인, 온라인 에이전트 최대 둘)가 보냅니다. 직접 깨우려면 `pumasi node wake 노드`, 대시보드 노드 화면의 **깨우기** 버튼, `POST /api/v1/nodes/노드/wake`를 씁니다. macOS, Windows, Linux, BIOS 설정은 README의 "잠드는 기기"에 있습니다.
- **`executor = "image"`.** Docker가 있는 노드에서는 Docker로, microVM만 있는 노드(구형 Mac, Docker Desktop 없는 PC)에서는 microVM으로 도는 이미지 작업입니다. `pumasi job ID`가 태스크별로 `as=docker`나 `as=microvm`을 보여 주고, API에는 `ran_as`가 있으며, 요금은 실제로 돈 실행기 기준입니다. 예제는 `examples/python-wordcount/job-image.toml`입니다.
- **Windows 서비스에서도 `--idle-minutes`가 동작합니다.** 에이전트 서비스가 로그인한 사용자 세션에 창 없는 도우미(`pumasi idle-helper`)를 띄워 유휴 시간을 읽습니다. 로그인한 사람이 없으면 유휴로 봅니다. 따로 설정할 것은 없습니다.
- **`--on-pause requeue`.** 기기가 일시 정지하면(배터리, 사용자 입력, 시간대 밖) 돌던 태스크를 끝까지 돌리지 않고 바로 다른 노드로 옮깁니다. 기본값은 `finish` 그대로입니다.
- **2013~2014년 Mac에 Linux를 설치하는 안내**: [docs/linux-on-old-macs.md](../linux-on-old-macs.md) (영문).
- **주의.** 새 옵션은 `pumasi service set -- --wake-on-lan`처럼 켭니다. 에이전트는 기기의 Wake-on-LAN 설정을 바꾸지 않고, Wi-Fi 카드는 거의 깨어나지 않습니다. 같은 LAN에 클러스터 기기가 하나뿐이면 깨울 수 없습니다. 잠든다고 알린 노드만 자동으로 깨우며, 꺼진 기기는 `pumasi node wake`로 직접 깨웁니다. 1.5 미만 CLI와 대시보드는 image 작업을 표시하지 못합니다.
- **업그레이드.** 프로토콜(14)과 저장 형식(7)은 그대로입니다. 1.4 클러스터는 `pumasi upgrade latest`나 대시보드의 업그레이드 버튼으로 올라가며 순서는 상관없습니다. 새 기능은 컨트롤 플레인과 에이전트가 모두 1.5여야 동작합니다.
