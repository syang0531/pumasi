# Pumasi 1.6.0

Monitoring everywhere. A microVM task's output now shows while it runs,
GPUs of every vendor report their use, Windows PCs report temperatures,
the last hour of metrics survives a restart, the cluster measures the
network between its nodes, and alerts can be silenced, repeated and
tuned per node.

## Install

```sh
curl -fsSL https://github.com/syang0531/pumasi/releases/latest/download/install.sh | sh
```

On Windows, from an administrator PowerShell:
`irm https://github.com/syang0531/pumasi/releases/latest/download/install.ps1 | iex`.
The protocol (14) and the stored state's layout (7) are unchanged; a 1.5
cluster upgrades with `pumasi upgrade latest` (or the dashboard's Upgrade
button), in any order. Live microVM output and network probes need both
sides on 1.6; a 1.5 agent in a 1.6 cluster works as before.

## New

- **Live microVM output.** `pumasi logs -f`, the dashboard and
  `GET /api/v1/jobs/ID/tasks/N/logs` follow a microVM task's stdout and
  stderr within a second, on every backend (Firecracker, QEMU, WHPX and
  Virtualization.framework), as they already did for Docker and WASM.
  The first MiB of each stream is live; the rest comes when the task
  ends, and the result still comes from the guest's output disk.
- **GPU use for every vendor.** Intel, AMD and Apple GPUs report use and
  memory in `pumasi top`, `pumasi metrics`, the dashboard and Prometheus:
  DRM fdinfo and sysfs on Linux, IOAccelerator statistics on macOS (the
  2014 iMac's AMD GPU included), and the GPU Engine performance counters
  on Windows, where Intel and AMD GPUs are now listed at all.
- **Temperatures on Windows**, through WMI: ACPI thermal zones, and
  LibreHardwareMonitor's CPU and GPU sensors while it runs (most desktop
  boards need it; run it once as administrator with "Run on Windows
  startup").
- **The last hour survives a restart.** The 10-second steps are written
  with the rest of the metrics, and the unfinished steps at shutdown.
- **The network between nodes.** Agents measure each other over iroh:
  five round trips and a 1 MiB transfer, one pair every 20 seconds (with
  five nodes each direction every 7 minutes, under 60 KB/s in all), at
  most 16 MiB a minute into any agent. `pumasi net` prints the matrix,
  the dashboard's node list shows it, `GET /api/v1/net` returns it, and
  a node fetching from the file store tries the closest other node's
  cache first. `pumasi cluster start --net-probe-every 1m` (or `off`)
  changes the pace.
- **Alerts.**
  - Silences: `pumasi alert silence [RULE] [--on NODE|SELECTOR] [--for 2h]
    [--comment ...]` keeps matching alerts from sending notices (they
    still show as firing); `pumasi alert unsilence ID` ends one early.
    The dashboard's Events page adds and ends them too, and
    `POST /api/v1/alerts/silences` / `DELETE /api/v1/alerts/silences/ID`.
  - Repeat and resolved notices: `pumasi alert set --repeat 4h` sends a
    firing alert again every four hours; `--resolved off` stops the
    "resolved" notices.
  - Per-node thresholds: `pumasi alert set --on laptop --node-offline off`
    or `--on gpu=nvidia --temperature 85` (node offline, disk and
    temperature; `inherit` drops them). A node name wins over a label.
  - A **Send a test** button for each webhook on the Events page, and
    `POST /api/v1/webhooks/NAME/test`.

## Notes

- The guest streams over the console it already has, not a new virtio
  console as planned (Firecracker has none); a line the console loses
  ends that stream's live copy, never the result.
- Per-node thresholds and silences are set with the CLI, the API or the
  dashboard; `cluster.toml` (`apply`) keeps only the cluster-wide rules.
  Editing the rules themselves in the dashboard comes with 1.7.
- DRM fdinfo shows only processes the agent may read: an agent running
  as an ordinary user does not see other users' GPU work. Intel and Apple
  GPUs report no temperature or power.
- Checked by hand, not in CI: live output on the iMac (vz) and a Windows
  PC (WHPX), Windows temperatures, and GPU use on the iMac's AMD GPU and
  an Intel GPU. CI checks the live stream on Linux microVMs (KVM), the
  restart, the probe matrix between local agents and silences.

## 한국어 요약

- **microVM 실시간 출력.** `pumasi logs -f`, 대시보드, API가 microVM 태스크의 stdout·stderr를 실행 중에 1초 안에 보여 줍니다(Firecracker, QEMU, WHPX, Virtualization.framework 모두). 스트림마다 처음 1 MiB까지 실시간이고, 나머지와 최종 결과는 태스크가 끝날 때 게스트의 출력 디스크에서 옵니다.
- **모든 제조사의 GPU 사용률.** Intel·AMD·Apple GPU의 사용률과 메모리가 `pumasi top`, `pumasi metrics`, 대시보드, Prometheus에 나옵니다(Linux는 DRM fdinfo와 sysfs, macOS는 IOAccelerator 통계로 2014 iMac의 AMD GPU 포함, Windows는 GPU Engine 성능 카운터로 Intel·AMD GPU도 목록에 나타남).
- **Windows 온도.** WMI로 ACPI 열 영역과, LibreHardwareMonitor가 실행 중이면 그 CPU·GPU 센서를 읽습니다. 데스크톱 보드는 대부분 LibreHardwareMonitor가 있어야 합니다(관리자 권한으로 한 번 실행하고 "Run on Windows startup" 켜기).
- **최근 1시간 지표가 재시작 뒤에도 남습니다.**
- **노드 사이 네트워크.** 에이전트끼리 iroh로 왕복 다섯 번과 1 MiB 전송을 잽니다(20초마다 한 쌍, 에이전트 하나가 받는 양은 1분에 16 MiB까지). `pumasi net`, 대시보드 노드 목록, `GET /api/v1/net`에 행렬로 나오고, 파일 저장소에서 받는 노드는 가장 가까운 노드의 캐시부터 찾습니다. 간격은 `pumasi cluster start --net-probe-every 1m`(또는 `off`)로 바꿉니다.
- **경보.** `pumasi alert silence [규칙] [--on 노드|셀렉터] [--for 2h] [--comment ...]`로 알림을 잠시 멈추고 `pumasi alert unsilence ID`로 일찍 끝냅니다(대시보드 이벤트 페이지와 API에서도). `--repeat 4h`로 울리는 경보를 다시 보내고, `--resolved off`로 해제 알림을 끕니다. `--on laptop --node-offline off`, `--on gpu=nvidia --temperature 85`처럼 노드·라벨별 기준을 둡니다. 웹훅마다 **테스트 보내기** 버튼이 생겼습니다.
- **주의.** 노드별 기준과 일시 중지는 `cluster.toml`에 넣을 수 없습니다(CLI, API, 대시보드). DRM fdinfo는 에이전트가 읽을 수 있는 프로세스만 보며, Intel·Apple GPU는 온도·전력이 없습니다.
- **업그레이드.** 프로토콜(14)과 저장 형식(7)은 그대로입니다. 1.5 클러스터는 `pumasi upgrade latest`나 대시보드의 업그레이드 버튼으로 올라가며 순서는 상관없습니다. 실시간 microVM 출력과 네트워크 측정은 컨트롤 플레인과 에이전트가 모두 1.6이어야 합니다.
